## 🔧 Technical Implementation

### **API Endpoints Created**

**Admin:**
- `POST /api/reports/admin/mothers`
- `POST /api/reports/admin/visits`
- `POST /api/reports/admin/vaccinations`
- `POST /api/reports/admin/summary`

**Midwife:**
- `POST /api/reports/midwife/mothers`
- `POST /api/reports/midwife/visits`
- `POST /api/reports/midwife/summary`

**Mother:**
- `POST /api/reports/mother/health`
- `POST /api/reports/mother/appointments`
- `POST /api/reports/mother/documents`

### **Request Format**
```json
{
  "range": "month",      // "week" | "month" | "quarter" | "year" | "all" | "custom"
  "startDate": "2024-01-01",  // Optional, for custom range
  "endDate": "2024-12-31"     // Optional, for custom range
}
```

### **Response**
- Content-Type: `application/pdf`
- Content-Disposition: `attachment; filename="report-name-date.pdf"`
- Binary PDF data

## 🚀 Usage Guide

### **For Administrators**
1. Navigate to `/reports`
2. Select report type (Mothers, Visits, Vaccinations, Summary)
3. Choose date range
4. Click "Generate Report"
5. PDF downloads automatically

### **For Midwives**
1. Navigate to `/midwife/reports`
2. Select report type (My Mothers, My Visits, Activity Summary)
3. Choose date range
4. Click "Generate Report"
5. PDF downloads with personal data

### **For Mothers**
1. Navigate to `/mother/reports`
2. Click on desired report card (Health, Appointments, Documents)
3. Click "Generate & Download Report"
4. PDF downloads with personal health information

## 🔒 Security Features

### **Role-Based Access Control**
- Admins: Can generate reports for all data
- Midwives: Only assigned mothers' data
- Mothers: Only their own personal data

### **Data Filtering**
- Each API endpoint validates user role
- Queries filtered by role (midwifeId, motherId)
- Unauthorized access returns 401/403 errors

### **Secure Data Handling**
- No sensitive data logged
- PDF generated server-side
- Direct binary streaming to client
- No temporary files stored

## 🐛 Troubleshooting

### **"Failed to generate report" error**
- Check if user is logged in
- Verify role permissions
- Check database connection
- Look at browser console for errors

### **PDF doesn't download**
- Check browser pop-up blocker
- Verify API endpoint returns PDF
- Check Content-Type header
- Test with different browser

### **Empty/incomplete data in report**
- Verify date range is correct
- Check if data exists for that period
- Confirm database has required relationships
- Review API response in Network tab

### **Permission denied**
- Verify user role matches endpoint
- Check session is valid
- Confirm user has motherId/midwifeId set
